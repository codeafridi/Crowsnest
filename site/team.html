What the relay holds

The shared state a single machine cannot.

The fleet

Every machine that reports, with silence detection (suspect at 1.5 times the learned interval, silent at 90 seconds), duplicate detection and pre-registration. The desktop Team page shows the same rows the browser does — and a silent machine is a dash, never a stale reading.

Incidents that wait

Threshold and composite rules over stored rollups, dependency and flap suppression, folding, and acknowledge, close and silence with an audit trail. A colleague can acknowledge from the desktop or the browser; the server is the truth both read.

Delivery

Email, webhook (the Alertmanager v4 body with an HMAC), Slack, PagerDuty, Opsgenie, Discord and Teams, driven by a routing tree with group wait, repeat, escalation steps and an on-call rota. A retry ladder and a dead letter queue; every send is one ledger row.

Your data, on your terms

Retention is stated and enforced by one function. Export is streamed as the desktop client's own CSV dialect or JSON. Delete is a real delete with a counts receipt, and an optional export bundle whose sha256 is in that receipt.

Getting started

Four steps. The relay is yours.

  1. Install the client on each machine you want in the fleet. It is the same free app; [remote] is off until you switch it on.
  2. Run the relay on a server you control — one static binary and a Postgres database. No link yet; managed hosting is not open.
  3. Mint an ingest token in the relay's dashboard. It is shown once; each machine gets its own.
  4. Point the client at it with three config lines. The report leaves the box only after the relay answers, and an offline spool buffers what the machine gathered while the laptop was closed.
crowsnest config
[remote] enabled = true url = https://relay.example.com token = the-machine-token

[remote] actions turns on the desktop verbs — acknowledge, close and a 30-minute silence from the Team page. Reading is on with the link alone, and a read-only token disables the verbs with the reason on the page.

The honest version

What you are buying, and what you are not.

  • The desktop app is never gated. Team adds shared state; it unlocks nothing on your machine. [remote] ships in the free build, off by default, and there is no licence check anywhere.
  • Shared state, not metered telemetry. The payload never carries process lists, command lines, environment, paths or logs — the schema refuses them and a test asserts it.
  • You run the relay. Managed hosting is not open yet. The relay is one static binary plus Postgres on your own server, and the trial starts when it begins serving your workspace.
  • Deletion is a real delete. Thirty days of grace after cancellation, then counted deletes child-first, a receipt, and an optional export whose sha256 is in the receipt.

FAQ

The questions people actually ask.

When does the trial start?

The day a relay you run begins serving your workspace — not when you sign up. It runs 14 days, needs no card, and carries the full Team limits.

What happens if I cancel, or a payment lapses?

Cancellation keeps the plan to the end of the period, then data is kept 30 days before a counted delete with a receipt. A lapsed payment gives 7 days of grace: read-only by day 7, cancelled by the pass on day 8. Restore inside the window and nothing is lost.

Is the free app limited?

No. Same binary, same 34 views, MIT. [remote] ships in the free build off by default; turning it on is the entire upgrade. Local telemetry is never metered.

Can I self-host today?

That is the only way today: one static relay binary plus Postgres on your own server. Managed hosting is not open yet, and the relay binary is MIT.
